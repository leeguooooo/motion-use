# Whiteboard — how motion-use checks a film

Takeaway: a film is code, every frame is computed from time, the delivered MP4 is measured, and a person still has to watch it. Facts from this repository's README and `references/film.md`.

Look: RSA-style whiteboard, black marker and one orange, the pen writing in time with the voice. Built from `M.signature`, `M.stroke` with `pen` and `rough`, `M.shoot`. The lights are an illustration of the report's motion lights, not a screenshot of it.

Beats: write draw.js, box it, note f(time) → arrow, three stacked frames → arrow, a film strip, three lights, the green one circled → "a person watches", underlined, pull back to the whole board.

Framing: the camera holds each idea at 1.9× (1.7× portrait) and pans as the arrow leaves; arrows start and end at each idea's measured extent; portrait aims a little below each idea to keep drawings above the subtitles. The closing overview is small by design: it shows the whole board.

Measured (draft renders, en/zh landscape): fast_ratio 0.067 (green), narration present. Not watched end to end; music not listened to.
